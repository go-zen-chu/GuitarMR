# @guitarmr/demo

A single HTML file that runs layoutscan in the browser, as the first step
toward the phone/tablet PWA (ADR-009): pick a scanned PDF, every page is
rendered with pdf.js and analyzed in a Web Worker on the device, the
detected systems (blue) and measures (red) are drawn over the upright page,
and the layout layer can be saved as `<name>.gts.json`. The PDF never
leaves the device.

```sh
pnpm --filter @guitarmr/demo build              # dist/layoutscan-demo.html
pnpm --filter @guitarmr/demo build --no-samples # without the embedded samples
```

- `scripts/build.ts` concatenates the layoutscan core and `src/` with their
  types stripped (Node's `stripTypeScriptTypes`; no bundler), embeds the
  two public-domain sample PDFs generated by `@guitarmr/samples`, and loads
  pdf.js (legacy build, for current iOS Safari) from jsDelivr at the
  version pinned in `package.json`.
- `src/app.ts` is the page; `src/preview.ts` and `src/worker.ts` run in the
  worker (detection plus a 1600 px upright preview).
- The output is a page body without `<html>`/`<head>` (it is published as a
  private claude.ai Artifact, which adds them and offers the save dialog).
  Opened from disk it also works; the save button then downloads directly.

`pnpm test` checks that the concatenated core detects exactly like the
modules and that the page only loads the pinned pdf.js and fonts.
